# IC 结构化解析与比赛运行验收

本轮按用户新贴计划优先处理引脚基础观测和比赛运行稳定性；GEA-Net、DirectionalFieldNet 继续冻结。计划中的 18.45 分是旧默认，本轮起点是上一轮新默认 26.5107 分。以下为公开开发集代理结果，不能当作官方成绩或独立泛化结论。

## 新增算法

新增 `StructureAwareICParser`。文本分支将图像观察到的端点分配到四条边，沿边排序，使用允许跳过的动态规划做 OCR 文本单调匹配。库提供编号与名称候选，排列次序来自当前页面 OCR 与端点，不假设封装编号沿图纸连续递增。同名电源引脚必须保留编号证据。

结构分支当前只修正左右两边已有编号的端点。改动必须同时具备唯一局部编号 OCR、对应编号的库内名称 OCR、同边序列对应和真实水平笔画。法向位置以检测器外框边估计，横向位置从实际笔画求出。无笔画、不支持的型号、编号冲突或远距离改动时弃权。检测器外框可能有偏差，此方法不保证每次找到符号引脚真实终点。

结构分支不读取 GT、页面编号或固定型号坐标，不生成新端点，不复制库内几何。改动后的观测重新经过已有拓扑和约束关联。Topology 三态、飞线合并和电路先验继续保留。

## 网络误差账本

新增 `scripts/audit_net_observations.py`，只用于诊断，输出 `output/net-observation-audit/gt10.json` 和 `pcb55.json`。同类型元件 IoU > 0.2，端点分别以 <5px / <30px 一对一对应；网络标记允许重叠，不与官方匹配等价，不参与推理。

10GT 中有 155 个网络带“端点缺失或距离过远”标记、75 个带“端点精度不足”标记、72 个带“身份不一致”标记、16 个带“可能分裂”标记、48 个带“可能合并”标记。55 页相应为 1936、551、598、269、615。这些不是互斥分类，不能据此计算“多少百分比由上游导致”的因果比例。成员对应不足以判定错误 junction，该项明确记录为需要空间证据。旧域标注不完整、随机电源编号和几何近邻误配也会影响诊断。

本轮不启动新的 junction 网络训练，也不使用 AMSNet 冻结池调参或评分。

## 使用候选

```powershell
.venv/Scripts/python.exe -m pcbparse infer data/examples/guide-schematic.png --ic-pin-mode structure --output output/ic-structure.json --diagnostics output/ic-structure-diagnostics.json
.venv/Scripts/python.exe agent_system -input data/examples -output output/ic-structure-agent --ic-pin-mode structure
# 保持已验证默认
.venv/Scripts/python.exe agent_system -input data/examples -output output/current-agent --ic-pin-mode none
```

候选需要已启用语义库。普通元件不进入此分支。顶部/底部几何、无编号端点补全、局部 OCR 重识别和独立新设计验证留作后续工作。

## 容器验收

比赛基础镜像已重新构建，包含可选候选入口，默认仍保持上一轮配置。`scripts/container_acceptance.py` 对 10GT 图片做 10 案例和 50 模拟案例运行，限制 2 CPU / 2GiB 内存 / 256 PID，断网且输入只读，不挂载 GT JSON。50 案例为 10 图各重复 5 次，只测试吞吐与稳定性，不能视作 50 个独立准确率样本。

测量项包括平均与 p95 时间、超时率、OOM、token、输入 SHA256 不变，以及与 Windows 默认 JSON 一致性。内存来自抽样 `docker stats` 工作集，可能漏掉瞬时峰值，不声称是 cgroup 精确峰值。限制为本地测试选择，官方 runner 完整资源与日志要求仍待核验。最终数据见 `output/container-batch-acceptance.json`，单例历史验证见 `output/container-validation.json`。
