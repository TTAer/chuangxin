# Top-K IC 型号检索与引脚证据消歧

更新：2026-10-05。本轮依据用户提供的评估，冻结 SideStripNet 网络、阈值和合成扩量，转向身份覆盖。新增检索模块与可选自动识别入口，完成真实图片、代理评分和部署对照；默认不切换。未训练新 CNN，正式技术报告继续暂缓。

## 新增算法

`ICIdentityResolver` 从已检测 IC 的局部 OCR 与当前 Name 召回最多 5 个型号。正常字符串相似度、0/O 等混淆折叠、型号前缀支持候选召回；混淆折叠与家族前缀不能独立确认型号。

只拆分有明确格式的粘连前缀，例如 `R12HS96L03W2C03`、`10uAMS1117-5.0`、`C7AMS1117-3.3`。不是任意寻找型号子串。当前 Name 来源仍是 OCR，不作为第二份独立证据。

候选按 0.8×词形得分 + 0.2×引脚证据 − 编号名称冲突惩罚排序。引脚证据来自原有编号端点附近的可见名称，以及 IC 局部高置信度文本；不读取 GT。确认要求至少两个不同的可见引脚名称、无已知编号名称冲突，并有第二候选 margin。直接词形相似度≥0.94 时要求 margin≥0.035；家族/混淆候选必须额外具有至少三个编号引脚证据，margin≥0.06。证据不足则保留 Top-K 并弃权。

已被原有严格检索确认的型号保留。只有新确认的元件执行额外语义关联，避免对其他元件重复运行关联而混入收益。端点坐标不从元件库复制；未知模型不会强制替换成相似型号。

**现有元件库没有图像四边顺序。** 因此本轮没有实现“按库数字编号排列 GND/VDD 上下文”的推断。数字编号顺序不一定等于 EDA 符号图像顺序；要实现评估建议的完整 Pin Sequence Solver，须先取得可验证的符号侧别和次序数据。已有单调 OCR 对齐继续使用图像观察顺序。

## 身份与元件输出审计

审计在推理后才读取开发 GT，IoU≥0.3 仅用于诊断，不参与运行期关联，也不是官方检测匹配规则。

| 阶段 | 10GT | PCB55 |
| --- | ---: | ---: |
| GT 标记为 box/ic 的元件 | 21 | 260 |
| 与原始 Box/Block 检测几何匹配 | 21 | 227 |
| 几何匹配且最终输出为 IC | 15 | 85 |
| 输出 key 正确 | 15 | 63 |
| GT 型号可在现有库精确找到 | 15 | 51 |
| 当前实际输出 IC 数 | 15 | 88 |
| 严格身份确认，改进前 | 10 | 21 |
| 严格身份确认，改进后 | 10 | 24 |

GT 的 box/ic 包括连接器及部分非芯片方框，不能把 260 当成 260 个真实芯片，也不能把粗几何匹配当作检测正确率。库精确覆盖统计忽略别名，带有此限制。检测到但未正确输出身份的缺口仍很大，须进一步检查位号竞争与漏输出。

PCB55 身份确认从 21/88=23.9% 提高到 24/88=27.3%，没有达到评估建议的 40%。原有 67 个未确认 IC 中，3 个确认、61 个无足够相似候选、3 个候选证据不足；这是当前数据与检索阈值下的分类，不证明所有未知实例都不存在于库。

10GT 五个未确认输出型号本轮都没有可靠候选。TP4054-MS、TPS61240DRVR、STMPS2141STR、MP2236CGJ-Z 等不能用近似的其他器件 schema 替代。单靠 fuzzy search 无法解决库缺失问题。审计证据见 `output/ablation/ic-identity-audit.json`。

## 自动运行与部署

```powershell
.venv/Scripts/python.exe -m pcbparse infer data/examples/guide-schematic.png --ic-identity-mode retrieval --side-pin-model models/candidates/side-strip-local/side-strip.onnx --side-name-anchors --output output/identity-example.json
.venv/Scripts/python.exe agent_system -input data/examples -output output/identity-agent --ic-identity-mode retrieval --side-pin-model models/candidates/side-strip-local/side-strip.onnx --side-name-anchors
```

`--ic-identity-mode none` 为默认。身份检索要求元件库及完整图模式；推理期不需要 PyTorch，不调用在线大模型。

新镜像标签 `graphschematic-identity:20261005`，ID `sha256:e84d6832bc915cc3f584d4ad706fb6bc257d22cfe681b2fd2f0ea82e9475fab2`。新镜像默认单例与 Windows 完全一致；50 个运行源码/部署模型文件哈希与工作区一致。当前可选分支 50 例混合批验单独保存于 `output/container-identity-20261005-batch-acceptance.json`。输入只包含 PNG、断网、只读、2 CPU / 2 GiB；8 张 10GT 和 PCB0006/0184 共 10 张图重复五遍，不是 50 个独立识别样本。

批验对型号、编号、名称、网络成员要求完全一致，几何浮点差要求小于 0.001 像素；有微小浮点差时不能称 JSON 数值完全一致。内存为 Docker stats 采样工作集，不是精确 RSS 峰值。当前新镜像默认分支只做单例，完整 10/50 默认分支记录仍属于上轮镜像，不重新标记镜像 ID。最终状态以本轮验收文件和开发包 manifest 为准。

50 例完整可选分支批验已通过：零失败、零超时、零 OOM；型号、编号、名称、网络成员 50/50 一致，35/50 数值 JSON 完全一致，其余仅有最大 0.0000040532 像素的几何浮点差。平均 7.4760 秒、P95 9.6588 秒、总耗时 374.1209 秒，采样工作集峰值约 824 MiB。输入哈希不变，LLM 调用与 token 用量为零；期间有其他本地实验并发，不是隔离性能基准。
