# PinTokenNet：文字与引脚身份联合绑定试验

2026-10-05：已完成独立 V1 小模型试验，详见 [实际训练结果](PIN_TOKEN_V1_RESULTS.md)。两组模型均低于最近端点基线，未接入 RC0。以下为试验前方案记录。

本方案由 RC0 评估导出，当前是待执行试验，不是已训练或已涨分的模型。RC0 保持冻结，训练产物放到独立候选目录。

## 新视角

把问题从“增加引脚端点”改为“为现有端点选择有图像证据的身份”。局部高分辨率 OCR 在 13 个缺位号样本中恢复 10 个；跨域原始框到输出存在明显损失。二者说明文字证据与身份绑定值得优先研究，但不能证明新模型必定有效。

候选输入为元件框四边的高分辨率条带、冻结端点提案、OCR token 位置与文字、型号库候选，以及局部物理导线组。输出分开表示元件位号/型号、每个端点的 pin number/name/null、身份置信度和电气连接权限。

## 模型与约束

1. 共享局部图像编码器提取字符笔画；数字/短文本采用 CTC 辅助识别。OCR token 嵌入与端点特征通过跨注意力交互。
2. 指针头在 token 与 endpoint 之间做关联，显式提供 null 类，允许缺字、缺引脚和多 token 名称。四边分别做有缺项的顺序对齐；不同边不强行共享编号方向。
3. 联合损失包含字符 CTC、真实 token—pin 配对监督、边归属以及重复编号惩罚。目录中的引脚表只约束合法候选，不能在缺少图像证据时按侧边顺序直接生成编号。
4. 已确认的旧身份保留锁定；新绑定经局部文字与笔画证据检查。电气权限仍由实际导线接触和跨物理网络冲突决定，不能由文字头决定。飞线标签的合法合并继续保留。

几何图与电气超图继续分开。Topology perception module 的判断优先拓扑和几何，颜色仅作为输入特征。实验不得以提高总分为由吞掉旧引脚、修改物理导线或强行连网。

## 数据与对照

先使用已有可追溯训练数据，按原始设计族分训练/验证；合成重渲染同族不可跨集合。增加真实原理图小字体、旋转、粘连数字、型号近似和无文字负例。可见 OCR 缺失样本只能纳入开发诊断，不得计为新独立测试。Freeze-A/B 完全保留，不参与参数或架构选择。

依次比较：冻结 RC0；局部高分辨率 OCR；局部字符头；字符头+指针绑定。所有组共用端点提案和电气保护，才能区分文字识别与关联收益。首先报告 pin number/name 的精确匹配、重复/幻觉编号、旧身份破坏率，再做整图 Pin/Net/Line 代理评分、运行时间与内存对照。不得只报告 oracle 框上的涨分。若整图未改善、原有正确身份被破坏或 NetLineF1 持续退步，保持关闭。

## 新数据来源的候选

[Microsoft SchGen](https://github.com/microsoft/SchGen/blob/main/README.md) 提供 KiCad 原理图、语义代码等数据，来源包含 SparkFun 开源硬件。可作为真实设计族及可控重渲染的候选，但需要核查每项许可、下载清单、KiCad 版本、跨数据集设计重合和人工标注；不能直接算已新增的 PNG/电气 GT 数据集。

[Netlistify 作者仓库](https://github.com/NYCU-AI-EDA/Netlistify/blob/main/README.md) 提供元件/方向与连接恢复相关实现及数据入口，可用于方法对照。此前发现其数据入口需要授权；本轮没有取得数据，不绕过访问条件，也不将论文描述算作数据已到位。

先完成同域独立评估的样本采集与冻结，再确定上述数据用于训练还是独立测试；一个设计族只能承担一种角色。
