# PortLift：从准确端口Oracle推进到候选附着边界

2026-10-07。结论：冻结模型能处理已知三/四端口聚合，但附着错误明显破坏整页关系；新增保守候选上下界，保持研究隔离。**本轮没有重训权重，没有独立真实精度，没有RC0接入。**

三/四端口测试不需改权重，因为V1的端口汇总本身支持可变P；此前实际训练只有P=2。本结果是已知端口附着的聚合可扩展性，不是识别真实三端晶体管或多引脚IC。四端队列正组件对2831/2880，非常稠密，不能仅凭满分宣称泛化强；端口归属仍由编译器提供。

压力结果说明当前缺口在观察附着，而非端口数量。把错误wire ID当唯一观察，模型没有候选位置、端点视觉或身份信息可用；用更多标签逼它“纠正”会制造不可观察目标。因此本轮不进行新的模型训练。

## 新模块：条件成立的关系上下界

`experiments/port_lift_uncertainty.py`接收物理wire关系、每端口的多个wire候选、候选mask、端口mask、候选完整性证据mask。组件内部仍不添加导线边，组件关系仍不做传递闭包。

对每一对端口，计算其所有候选组合中的最小/最大关系；再对两个组件的端口对取最大值。下界是保守的充分条件，不声称精确求解所有联合约束；上界表示这些候选允许的可能连接。存在至少一对端口在所有组合下同网时，可确定组件共享net；任何组合都不共享时，可确定不共享；其他关系unknown。

该保证以“真实附着在候选集合内、观察端口集合符合目标范围、物理wire关系正确”为条件。它不从模型置信度推导候选完整性，不保证候选召回，也不能把上游错误物理图纠正为真值。

**默认candidate_complete未提供时为false**。未证明完整的端口对下界0、上界1；缺失候选也按unknown处理。部分有证据的端口仍可支持确定正关系，但缺失端口会阻止无依据的确定负关系。全页完整性未确认时，默认全unknown，不自动发布net合并。

## 核验与交付

- 候选顺序置换、缺失候选行为检查通过；32个随机小图分别穷举64种端口选择，确认下界不超过实际最小关系、上界不小于实际最大关系。
- 模块验证输入维度、整数ID、二值mask、有限且位于[0,1]的物理关系，默认完整性为false。
- 旧PortLift21项、ProbeFlow121项、RC0 53项SHA均无变化。
- 压力测试：`scripts/stress_port_lift_observations.py`，结果`output/port-lift-observation-stress/final/report.json`。
- 候选审计：`scripts/audit_port_lift_uncertainty.py`，最终结果`output/port-lift-uncertainty/final/audit.json`及`relation-bounds.npz`。
- 初次压力/边界诊断和保护修正核查都保留，不覆盖原记录；相同队列重复实现核验不计新增独立数据。
- 本轮冻结：`output/port-lift-uncertainty-manifest.json`。

下一步真正需要的是真实端点观察产生的候选列表及可追溯候选召回证据。取得这些输入后，才能决定是否训练附着评分器、加入视觉上下文或继续维持abstention。本轮先明确模型信息边界，不把真实组件关联资料伪造为端口监督。人工A/B仍0/25、独立verified designs仍0、官方scorer等价性仍unresolved。
