# IC 候选过滤、检测框训练与名称增补

更新：2026-10-05。按两份建议，本轮保持局部卷积模型规模，优先检查候选如何进入最终电气图。默认配置保持不变；正式技术报告继续暂缓。以下均为开发代理评估。

## 候选过滤过程

新增每个 IC 的诊断：条带数、阈值峰、轴向范围过滤、灰度笔画过滤、NMS 候选、元件库身份、已编号候选、接受新增/修正。诊断不读取真值，不参与推理选择。

| local 阈值 0.5 | 10GT | PCB55 |
| --- | ---: | ---: |
| 观测中的 IC 数 | 15 | 88 |
| 元件库身份确认 | 10 | 21 |
| 学习候选，NMS 后 | 91 | 953 |
| 数字/结构关联前编号候选 | 26 | 315 |
| 接受新增引脚 | 0 | 17 |
| 接受修正已有引脚 | 25 | 55 |
| 观测有修改的页面 | 1 | 8 |

10GT 的改善来自第 1 页 U1：27 个端点候选、26 个数字编号关联、修正 25 个已有引脚，没有新增引脚。其他已识别型号的 IC 多数产生了端点候选，但数字编号关联为零。因此此前涨分不能称为新增端点召回带来的收益。候选数量也不是 endpoint recall；后者需要独立的几何真值匹配审计。

PCB55 观测修改页数大于评分改善页数，说明未匹配身份、标注覆盖及网络重建仍会阻断收益。大部分 IC 无法确认元件库身份，不能靠增大端点网络解决。

对 base/local 各做 0.2–0.9 八档阈值，两域共 32 组整图重建，上游复用检测/OCR 缓存，条带推理和图重建实际执行。原模型文件与元数据阈值不修改，默认不按扫描结果切换。

| 0.4 | 28.4846 | 16.7368 | 28.8156 | 16.7454 |

local 在 0.2–0.6 的 10GT 得分完全相同；降低阈值增加候选，没有恢复更多可评分引脚。高阈值会损失收益。base 在两个域的偏好不同，没有普遍最优阈值。

结构文字解析器还会处理已有引脚，所以阈值 0.9、学习候选为零时，仍可能有语义观测修正。不要把所有接受修改数当成学习网络贡献。记录见 `output/ablation/side-thresholds.json`、同名 CSV。

## 检测框条件训练

在既有官方 160/40 页划分上执行当前 YOLO 检测，只用几何 IoU≥0.3 的一对一 IC 匹配构建监督裁剪：训练 701 个符合条件 IC 匹配到 698 个，验证 198 个匹配到 185 个。匹配仅用于准备训练标签，推理不会读取它。

同一 IC 构建两组输入：标注主体与端点联合框、真实检测框。训练均使用原框及共享的四条边独立 ±6 像素扰动，验证不扰动；均为局部卷积、11,738 参数、同种子 20261006、从头训练 6 epoch，未使用 SidePinBench、10GT 或冻结 AMSNet。

标注框组训练/验证条带 6,594 / 878，检测框组 6,672 / 882。这些是既有数据的重新裁剪，不是新增独立设计。两组条带数量、优化步数略不同。检测框监督有训练 12、验证 30 个端点窗口实例超出 ±30 像素法向范围，被排除并记录；跨窗口实例不等于独立端点数。

两模型在各自验证裁剪选择 checkpoint；再用固定阈值 0.5，对同一裁剪域交叉比较：

| 验证输入框 | 标注框训练 F1 | 检测框训练 F1 |
| --- | ---: | ---: |
| 标注框 | 0.8891 | 0.8882 |
| 检测框 | 0.7781 | 0.7801 |

输入框改变造成的退步明显，检测框训练只恢复很小一部分，尚未解决分布差异。两组整图结果：

| 候选 | 10GT 代理分 | PCB55 代理分 |
| --- | ---: | ---: |
| 配对标注框训练 | 28.3763 | 16.7410 |
| 配对检测框训练 | 28.5513 | 16.7481 |
| 上轮 local | 28.8156 | 16.7454 |

检测框候选未同时超过上轮 local，继续保留实验候选。两组均完成固定 16 条带 PyTorch/ONNX 对照，法向误差最大 0.0001722 像素；分别对实际第 1 页和 PCB0184 从图像重放，与缓存结果完全一致。其余整图实验仍为实际条带推理加缓存上游，不能声称所有页面都重新执行 OCR。

## 唯一名称驱动的增量编号恢复

新增可选 `--side-name-anchors`，必须同时指定 `--side-pin-model`。利用图像观察到的唯一名称恢复其元件库编号，不假设库里的数值编号等于图像沿边顺序。要求已确认型号、高置信度名称 OCR、相同边、局部轴向位置、跨编号唯一性与匹配间隔，并由实际垂直于主体边的七像素灰度笔画验证。

已有编号不从名称分支重新赋值；保留原引脚，只增补缺失身份。重复 GND/VDD、邻近候选难区分、笔画不足均弃权。现有数字编号和结构对齐分支仍可修正原有引脚。

最初允许名称恢复同时修改已有引脚的研究对照，10GT Pin 略升但 Net/Line 回退，得分 28.7770；因此收紧为上述增量规则。最终结果：

| 配置 | 10GT Pin / Net / 分数 | PCB55 Pin / Net / 分数 |
| --- | --- | --- |
| 默认 | 0.1395 / 0.0997 / 26.5107 | 0.1023 / 0.1991 / 16.7037 |
| 上轮 local | 0.1811 / 0.1263 / 28.8156 | 0.1024 / 0.2002 / 16.7454 |
| local + 增量名称 | 0.1811 / 0.1263 / 28.8156 | 0.1028 / 0.2004 / 16.7617 |

PCB55 相对默认 4 页改善、0 页评分退步、51 页相同；观测接受新增总数为 25，不能称这 25 个都正确，部分来自已有结构关联。10GT 仍只有一页评分改善，未跨过 Pin>0.20、Net>0.15；PCB55 增益 0.0580，低于建议的 0.1 门槛。默认保持关闭。

最终增量分支对 10GT 全部 10 页，以及 PCB55 所有观测变化页加控制页共 9 页，从实际图像重放，19 页与缓存结果完全一致。79 项功能测试通过，包括名称唯一性、重复名称弃权、已有编号保护、实际笔画和边界检查。

```powershell
.venv/Scripts/python.exe -m pcbparse infer data/examples/guide-schematic.png --side-pin-model models/candidates/side-strip-local/side-strip.onnx --side-name-anchors --output output/side-incremental-example.json
.venv/Scripts/python.exe scripts/prepare_detector_side_strips.py
.venv/Scripts/python.exe scripts/sweep_side_thresholds.py
```

完整训练、过滤与整图记录见 `output/ablation/side-refinement.json`。可运行开发包包含两组新 ONNX 及元数据，不包含原始训练图像或 checkpoint。
