# PinTokenNet-R：难例挖掘与几何锚定纠错（2026-10-05）

本轮完成全量现有训练来源的难例挖掘、两组表格模型、局部 OCR 预处理诊断和首个 CAD→像素标注样本。RC0 不切默认；V1 作为 research negative result 冻结，新增 `data/splits/pin-token-v1-frozen.json` 固定89个数据/代码/权重/评估文件，RC0 原53个运行文件和权重哈希不变。

## 难例数据

从官方200训练来源中，排除像素重复与已声明排除页后，198页与 CVJson 逐像素对齐，158页训练、40页开发验证。另沿用保守结构分组，验证设计结构组不进入训练；这仍不是经过原始设计来源证明的独立测试。

实际 OCR 与明确文本引用唯一对齐后得到8,906个监督token：训练7,085、验证1,821。未知角色、共享引用和未唯一匹配文字不当作负样本；18,308个OCR token被排除，一个真实引用不在几何top8候选中。身体框和端点来自标注，因此只评价条件局部关联。

| 关联标签统计 | 训练 | 开发验证 |
|---|---:|---:|
| pin token | 4,886 | 1,067 |
| 最近端点正确 | 4,639 | 1,011 |
| 最近端点错误、正确端点在top8 | 247 | 56 |
| 明确非pin角色token | 2,199 | 754 |

303个难例的多标签诊断：同边邻近267、跨边36、文字跨度覆盖多个候选127、角点49、竖向OCR框22、长字符串14、真实目标不在top3共8；分类可以重叠，不是人工裁决的成因。56个难例的number字段不符合简短编号语法，9个存在编号/位号歧义。全部pin token中另有训练229、验证55个number格式待审，不能把 source `pinNumberByOCR` 当审核真值。

逐条证据见 `output/ablation/pin-token-hard-mining.json`。候选和特征选择均不读取目标身份；真实引用只用于训练标签与后验诊断，没有顺序补号。

## Residual 表格对照

几何最近端点为默认答案。固定margin安全锚点不允许覆盖；仅不安全锚点且wrong score达到阈值、第二/第三候选置信度≥0.9时允许切换。role头缩为pin number / pin name / 显式非pin，未知signal等没有负样本监督。未训练新神经网络，也未使用视觉分支。

训练内按结构族hash抽出校准组，fit 5,150 token、校准1,935 token；最终开发验证1,821 token不参与阈值选择。阈值固定候选为0.95、0.975、0.99、1.01（关闭）；校准需至少10次切换、切换正确率≥95%、EPR>99%。这些是操作点选择，分类器概率没有经过概率校准。

| 开发验证pin token指标 | 最近端点 | Logistic exception + tree reranker | ExtraTrees exception + reranker |
|---|---:|---:|---:|
| 选定阈值 | — | 0.95 | 1.01（关闭） |
| 正确率 | 94.7516% | 95.3140% | 94.7516% |
| 易例破坏 | 0/1,011 | 3/1,011 | 0/1,011 |
| EPR | 100% | 99.7033% | 100% |
| 难例恢复 | 0/56 | 9/56 | 0/56 |
| HRR | 0% | 16.0714% | 0% |

Logistic的13次切换中9次正确、3次破坏易例、1次把原错误答案改成另一个错误答案。净增加6个正确关联，但HRR低于预先声明的25%门槛，也低于用户建议的20%下限。9个恢复中 `ADC1`、`VMAIN11` 的number角色本身可疑，不能据此声称恢复了9个合法引脚编号。树模型在校准组无足够可靠切换，自动关闭。

决策：两组均 `STOP_no_end_to_end_integration`。没有扫描开发验证阈值以制造过关结果，不扩大视觉模型，不接入整图；PinF1与NetF1保持未评，没有官方收益数字。

## Role 头不能删除原有锚点

三分类role macro F1为0.94735，但如果直接把预测non-pin当成删除原几何答案，Logistic组合会破坏43个易例，EPR降到95.7468%，并在754个显式非pin token中产生39个错误绑定。这是替换角色判断的风险消融，不能用单独role F1掩盖。

残差策略中，role拒绝一个已有合法锚点应表示“不提供纠错证据、保留旧答案”，不能删除旧身份。该保留策略的指标与上表Logistic相同，但仍不满足HRR门槛。未知/非pin token没有已有锚点时，keep不能授权新绑定。上述实验不是整图新token自动识别流水线。

见 `output/ablation/pin-token-residual.json` 与补充 `pin-token-residual-audit.json`；后者保存每次修改及标签风险。

## 局部 OCR 的实际进展

[局部pin OCR报告](LOCAL_PIN_OCR_RESULTS.md)发现旧 `min1600` 会把紧裁图强制放大，native/2×/3×首样本实际detector输入均为1600×3136。旧固定实验保留20/48已执行条目，明确partial；追加独立bounded-local协议，固定同48条仅跑2×。

新协议严格恢复number 9/24、name 11/24，number语法有效子集9/21。前20条可配对对照为旧2×恢复0、新模式恢复8；其余28条没有旧结果。仍有number 4、name 10条错误空间候选，GT文本框裁剪和弱引用评分都只能作为开发诊断，不能直接声称自动身份恢复或比赛PinF1提升。

## 复现与约束

按顺序运行 `prepare_pin_token_residual.py`、`mine_pin_token_hard_cases.py`、`train_pin_token_residual.py`、`audit_pin_token_residual.py`。准备/挖掘使用项目venv，训练使用已有scikit-learn 1.7.2环境。训练pickle只来自本地实验，不由比赛入口加载。

本轮新增的3项residual保护测试与2项局部OCR测试通过，总计115项测试通过。未改变RC0依赖声明、模型或入口，无需重复2×50部署验收。本轮支持继续研究保留几何锚点的文字证据，但还没有达到整图接入或RC晋级条件。
