# PortLiftNet：独立端口提升与非传递组件关联

2026-10-07。用户要求从新角度重新训练，本轮建立隔离研究实验。实际结果以`output/training/port-lift-v1/summary.json`和后续结果报告为准。

## 为什么改变任务

31页作者标注里25页存在组件共享net关系的非传递三元组。电阻B的两端可以分别与A、C共网，却不能推出A、C同网。因此不能把组件作为导电节点，不能对组件关系做连通分量。上一版ProbeFlow输出的是物理wire run分区，本轮将物理关系与器件关联分层，并实际训练不同的路径推断机制。

## 机制

1. 灰度候选交点patch输入CNN。四个90度方向平均，得到连接概率。
2. 仅沿观察到的导线候选边做最大乘积路径传播：R_ij=max(R_ij,R_ik R_kj)，遍历12个观察节点。使用可微max-product关系计算；没有拉普拉斯求逆、net query、或组件内部边。
3. 每个组件保留两个独立端口的观察到的wire归属P。共享net概率S_ab=max_{p∈a,q∈b} R_{P(p),P(q)}。组件可参与多个不同net；直接阈值输出组件对，禁止在S上做传递闭包。
4. 同时监督组件共享关系、物理wire可达关系和视觉交点。Loss=balanced_BCE(S)+0.5 balanced_BCE(R)+0.2 edge_BCE。单独监督R防止组件对满分掩盖物理图错误。

“器件屏障”指不人为添加器件内部的导线边，不指硬性禁止同一器件两端属于同一net。如果外部线路真实短接两个端口，仍允许正确同网。模型没有电气仿真，也不把通电路径当成同net路径。

本轮最多12条wire run、36个候选交点、10个组件×2个端口。导线图、交点和端口归属都是几何Oracle观察输入；**未自动检测真实器件/端点，也未实现多引脚IC**。输出组件对关系不是比赛pin/net格式，不能作为整页比赛准确率。

## 执行协议

固定seed20261007，4页tiny240步，组件与导线micro F1均至少0.95才继续；实际wire门槛登记在训练代码，protocol JSON仅命名组件门槛。tiny后重置到初始随机权重；不携带tiny拟合参数。

1024训练布局、128开发布局、128扰动布局，12轮，每批16，AdamW lr0.003。开发组件micro F1最大优先，同分选较低loss；扰动队列仅在选模后评分。独立seed与数据SHA记录在训练开始前保存。候选边truth与端口关系truth来自编译器生成过程；不是根据模型输出或真实图像猜真值。

导线视觉生成器沿用冻结ProbeFlow编译器，新模型、参数与端口关联编译器是新建。相同生成器不同seed不证明设计家族独立；随机端口归属也不满足真实电路功能分布。训练亮度/噪声来自编译器，另有固定seed控制的3×3平均池化模糊增强；扰动集90度旋转+Gaussian sigma0.7。

没有使用真实31页标注训练：它们只有组件关联，没有端口身份。新实验的目的就是先确认允许“同器件多net”的机制能否学会，而不是绕过来源/端口门禁。

组件对关系也不唯一决定电气超图：三组组件两两共享net，可能来自一个三成员net，也可能来自三个不同的二成员net。该汇总会丢失端口身份与net成员集合信息。本轮另用wire关系监督检验物理任务，不能声称仅凭作者组件对标签恢复完整pin-net集合。

## 必须看的对照

- 与全部组件对相连/全部断开比较。
- 把模型组件对错误做传递闭包，量化设备短路带来的额外误合并。
- 冻结ProbeFlow R2再加同样端口汇总，区分新端口任务的收益和传播机制的收益。该模型已在相同生成器上训练，不是公平从零训练消融；只能作为已有能力参照。
- 旋转、组件编号置换、wire编号置换和端口顺序交换不应改变语义结果。

只有受控任务的组件关系和物理关系同时成立，才值得后续接真实观察数据。若新机制不优于冻结模型，就保留端口提升的任务定义，停止声称传播优势。RC0、人工审核、独立verified与官方scorer等价性均不改变。
